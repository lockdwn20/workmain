## 1. Purpose

Issue #201 converts `meetings costs`, `notes costs`, `providers costs` and `reports costs` onto the direction #198 sets: a service returns what the command decided, and the command hands it to `workmain/cli/output.py`. The issue's census was measured on `main` `b61e321`, 20261012. This study re-measures it on `dev` `036ad12`, as §1.1 requires before a spec. It also settles the one thing the pilot (#58) did not build: a renderer surface for a result made of several parts.

## 2. Scope of the read

Read in full:

## 4. Options

### The service

Settled by existing rules, with no option to weigh:

- **Placement.** The read functions go in `workmain/services/ai_cost_service.py`, which already owns the domain. §3.6 prefers enhancing an existing module over adding one. Its module docstring is widened to cover reads. The recording functions keep their own sessions (§4.3), and the new read functions take the caller's session, as `tasks_service` does.
- **Shape.** Two functions, each returning a frozen dataclass. `condensation_costs(session, provider, start_date, end_date, limit)` serves `meetings costs` and `notes costs`. `report_costs(session, provider, report_type, start_date, end_date, limit)` serves `reports costs`. A third, `cost_summary(session, provider, start_date, end_date)`, serves `providers costs`. Each carries the totals, its breakdowns or detail as `Page`s whose `filters` name the period and any provider or type, and every F3 decision.
- **The condensation total.** The detail `Page.total` is `total_calls` (F5). The title then reads `N of M`, which is §5.6's title rule.
- **Formatters.** The view's `fmt` functions come from `cost_display.py`, the module that owns the domain (§5.6, "A view"): `format_thinking` as it is, plus count and cost formatters. `cost_display.py` keeps its pure formatters for F12's callers and loses the four `render_*` functions and every Rich import.
- **Arguments.** §5.6 says a converted command parses with Click types. `--date`, `--start` and `--end` take `DateParamType`. `--month` takes a new month type in `params.py`, which rejects a month outside 1–12 with `self.fail`. `--limit` takes `click.IntRange(min=1)` (§3.8). `resolve_date_window` then receives values that have already been parsed, and keeps its precedence and mutual-exclusion checks. Its tests in `tests/test_ai_costs.py` move with it. This changes the contract in F8 and F9: a bad value exits 2 as a usage error, instead of a traceback or a silent result. F17 shows the only callers are tests. `DateParamType` also accepts `today` and `yesterday`. Which forms every command accepts is #140's, and #140 changes the shared type once.
- **`--provider` and `--type`.** These keep `require_provider` and `require_report_type` unchanged (F10). Their printing and exit are #211's, and #211 is blocked by this issue. The results artifact names both calls as the one printing path left in the four functions, and #211 as the issue that removes it.
- **Errors.** The `except Exception` handlers go (F6). §5.6 says a converted command never exits 0 on an error, and has no `sys.exit`. An unexpected exception is reported by `WorkmAInGroup` (Q3).
- **Groups.** The four groups are declared `cls=WorkmAInGroup` (F11, §5.6). Under the root group nothing changes, and a direct invocation then behaves as the root does.
- **`__init__.py`.** `ai_cost_service` is imported and listed in `__all__` (AC6). F16's `email_service` is #205's (Q4).
- **Tests.** The tests in F14 that run a costs command are replaced by service tests (§6.2, Service) and one command test per command (§6.2, Command). The costs half of `TestReportTypeFiltersRows` leaves that test, and its `report_type` filter becomes a service test. The `reports list` and `corrections` halves stay for #212 (F15). AC5's sweep then names test nodes that this issue owns.

### Q1 — How a result in parts is rendered (F2)

#### Option A — a sectioned report view in the renderer

- **Approach:** `output.py` gains a `ReportView` and `Renderer.report(view, result)`. The view names the result's title noun, a `Totals` block (`Field`s, printed as aligned `Label: value` lines), and one or more sections. Each section names the result field holding a `Page` and a `CollectionView` for it. `report` prints the title from the result's filters, then the totals and each non-empty section through the existing `collection` layout. When the totals show no calls, it prints `collection`'s empty line and the view's hint instead. The command makes one call and passes the result unchanged, which is §5.6's converted-command contract as written.
- **Pros:** One call per command, with the result unchanged. Every table still goes through the table-or-list rule, so no value is cut and nothing depends on width. A typed result maps directly onto #222's `--format json`. #202 (`clockify status`, two tables) and #216 (`time today`, totals and a category breakdown) have the same shape and reuse it.
- **Cons:** A new renderer surface with its own tests in `tests/test_output.py`, and §5.6 text describing it. This issue writes that text (Q2).

#### Option B — the existing surfaces, called once per part

- **Approach:** The command calls `renderer.record` for the totals and `renderer.collection` once per breakdown or detail `Page`.
- **Pros:** No renderer change.
- **Cons:** A record's title is `<Resource> #<id> — <descriptor>`, and totals have no id, so the summary needs an invented id or a renderer change anyway. The command splits the result into its parts, which is the row-building §5.6 forbids a converted command. Each part prints its own title, so the period appears three or four times. This is the easy path, not the one the established contract describes.

**Recommendation: A.** §5.6 has a converted command pass one result, unchanged, to one renderer call. Only Option A keeps that contract for a result in parts, and two queued conversions need the same surface.
